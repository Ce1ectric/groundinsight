    Changelog¶

    All notable changes to groundinsight are documented in this file.

    The format is based on Keep a Changelog. Releases up to 0.6.0 followed Semantic Versioning; from the first release after 0.6.0 on, the project uses calendar versioning in the form YYYY.M.MICRO — the year, the month without a leading zero, and a counter that restarts at 0 in every month (2026.11.0, 2026.11.1, 2026.12.0, 2027.1.0). The month carries no leading zero because PEP 440 normalises 2026.01.0 to 2026.1.0, and a padded tag would never match the version on PyPI.

    A calendar version says when a release was cut, not whether it is compatible with the previous one. Two rules carry that promise instead:

    • Every change that can break working user code is listed under Breaking with a migration note, in addition to its regular entry.
    • A deprecated feature keeps working and emits a DeprecationWarning for at least two releases and six months before it is removed.

    Change categories follow the Keep-a-Changelog vocabulary, plus Breaking:

    • Breaking — changes that can break working user code, each with a migration note (also listed under their regular category).
    • Added — new features and public API.
    • Changed — behaviour changes to existing public API.
    • Deprecated — features that still work but will be removed.
    • Removed — features taken out of the public API.
    • Fixed — bug fixes.
    • Security — vulnerability fixes.
    • Docs — documentation-only changes.
    • Internal — refactors, tests, packaging, CI; no observable behaviour change.

    The backlog of ideas that are not yet scheduled is kept at the end of this file under Roadmap. During regular work, add your entry under the matching category in [Unreleased]; the release script (scripts/release.py) moves the whole [Unreleased] block into a new version section when a release is cut.

    Unreleased¶

    2026.11.0 was tagged but never published: the test gate of the release workflow stopped it before the build. This release carries its content unchanged; the notes are in the 2026.11.0 section below.

    Breaking¶

    Each item is detailed under its regular category below; this list is the migration checklist.

    • Version scheme. The first release after 0.6.0 is numbered by the calendar (YYYY.M.MICRO). A Poetry constraint such as groundinsight = "^0.6" will not pick it up; use groundinsight = ">=2026.11".
    • frequency_Hz is numeric in res_buses(), res_branches() and the sweep frames; the RMS rows are marked by the boolean column is_rms. Replace pl.col("frequency_Hz") == "RMS" with pl.col("is_rms") and == "50" with == 50.0. (OutageStudyResult.compare_*() keeps its string join key.)
    • network.paths is empty after a default run_fault. Call gi.create_paths(network) where the enumerated paths are needed as data.
    • Networks that used to solve silently now raise: an active element without an impedance at a solved frequency, kappa/n outside the IEC 60909 range, negative R/L/C/M fields in the state-space solver, assignments that violate a field validator, formulas calling functions outside the whitelist, bus_response on a stale nodal system, and ImportDefaults(frequencies=[]). Each message names the element and the fix.
    • Values change where the old ones were wrong: value_current with a source on the fault bus; BusResponse.evaluate (Z_G_Ohm, r_epr); I_th/i_p with a 0 Hz bin; analyze_cuts at 0 Hz and with Thévenin sources (new row source_loop); FFT transients with unreachable sources; the state-space solver with 0 Hz first in the frequency list, and its time series is one sample shorter.
    • Persistence. Databases written by 0.6.0 or earlier are migrated when they are opened (a backup is kept); JSON writes "inf" instead of the non-standard Infinity (old files still load); save_network refuses to rewrite a bus or branch type shared with another network unless overwrite_types=True.
    • Top-level API. gi.NetworkDB, gi.BusTypeDB and gi.BranchTypeDB are no longer re-exported; gi.Path is the domain model, not pathlib.Path; BusResponse.admittance lost its unused freq argument; the reference case en50522_chain now checks I_E.
    • Release tooling. The console command poetry run release is gone; run poetry run python scripts/release.py.
    • Dependencies. pillow 13.0.0 or newer is required (security floor, see Security). Upgrade pillow in the environment; if another package there caps pillow below 13, that package has to move first (SEC2).
    • State-space transients of meshed networks with mutual coupling change value. The phase current that drives the coupling is now divided between the routes of a ring or mesh like the stationary default phase_current_mode="auto"; before, every route carried the full source current. Chains, trees and networks without coupling are unchanged. Migration: there is no switch back — the old numbers were those of the legacy split (run_fault(..., phase_current_mode="paths"), still available stationarily). Branch.parallel_coefficient is no longer read by TransientStudy, and a state-space solve no longer fills network.paths; call gi.create_paths(network) where the paths are needed as data. (PH2)
    • session and db_session are no longer in groundinsight.__all__, and the session globals can no longer be assigned. A star import does not bind them any more, and assigning gi.session, gi.engine & co. no longer redirects the module-level persistence functions, which now use the default gi.Database. Migration: use the object that gi.start_dbsession(path) returns, or gi.Database(path) — db.session() yields a short-lived SQLAlchemy session, db.engine is the engine. Reading gi.session keeps working with a DeprecationWarning. (ARC2)
    • Formulas of a bus or branch type may only use the symbols the evaluator binds. A bus formula is evaluated with f and rho, a branch formula with f, rho and l; j, I, pi and E are available in both. Any other name (L, F, Rho, R + j*X …) used to be accepted and failed only at create_bus/create_branch with "Cannot convert expression to float"; it now raises when the type is created, naming the symbol, the allowed set and the case-insensitive match. Migration: write the symbols in lower case as listed; a bus formula has no l. (USE2)
    • Branch.length must be a finite length > 0 km. Zero, negative, NaN and infinite lengths are rejected at construction and on assignment, with a message about the length. They used to surface as "exactly zero impedance" or as a negative real part, and a detached branch was not checked at all. Migration: model a bus coupler or jumper with a short positive length (e.g. 0.001). A database or JSON file with such a branch no longer loads until the length is corrected. (USE5)
    • Tighter formula limits. Exponents above 12 (written out or computed, e.g. 10**-15, 9**(2*7)), number literals with more than 100 digits, hexadecimal/octal/binary literals, more than 512 terms, more than 8 calls or more than 3 arguments per call, floor/ceiling of a value with more than 100 digits and exp/sinh/cosh of an argument above 1e100 are rejected. No formula in the documentation, the notebooks or the test suite comes near any of them (at most 6 digits, exponent 2, 27 terms, 2 calls, 2 arguments). Migration: write small factors with an exponent part (1e-15 instead of 10**-15). (SEC1)
    • Edit invariants. Renaming a bus, branch, source or fault that belongs to a network, rewiring a branch, source or fault to a bus the network does not have, adding an element that belongs to another network, and assigning a field of a BusType/BranchType now raise ValueError. Migration: remove the element and add a renamed copy; add element.model_copy(deep=True) to a second network; change a type with new = bus_type.model_copy(update={...}) and network.update_bus(name, type=new). (GUI3, F9)
    • ResultReductionFactor.u_earthing / z_earthing and the grounding impedance are now the EN 50522 quantities at the fault bus. u_earthing is the EPR of the fault bus (U_E); z_earthing, ResultGroundingImpedance.value, Z_G in res_all_impedances() and Z_G_Ohm of bus_response are the driving-point impedance of the earthing network there (Z_E). Migration: the old values (the current-weighted mean potential of the earth group and that mean divided by I_E) are in u_earthing_group/z_earthing_group. A result stored before the change loads with its values moved to those fields, u_earthing/z_earthing and the grounding impedance left empty, and an info diagnostic LEGACY_EARTHING_DEFINITION; run the fault again to get U_E and Z_E. (PH4, F4)
    • run_fault raises ValueError for a source that has no value at any network frequency. Such a source used to contribute 0 A, and the run reported 0 V at every bus. Migration: give the source values at the network frequencies, or deactivate it. (USE3, F8)
    • Earth-return quantities that are undefined are None, not rounding noise. I_E, value_current and the earth group are None/[] when no electrode current exceeds 1e-9·|I_F|. The EPR-based value is None when the fault-bus EPR without coupling is below 1e-9·|I_F|·|Z_E|. Migration: code that turns these fields into floats has to handle None; the diagnostics EARTH_GROUP_UNDEFINED and REDUCTION_FACTOR_UNDEFINED give the reason. (P9, F14)
    • A real part of minus infinity is refused, not read as an open circuit. A bus formula with a log(f) term that no factor of f cancels, such as rho*0.01 + log(f), is −∞ at 0 Hz (log(0)). The passivity checks looked at finite values only, so −∞ passed and the solver read 1/(−∞) = 0: the electrode was disconnected at DC without a word — in a DC study and in the 0 Hz bin of every transient study, while a bin just above 0 Hz is refused for its negative real part (1 + log(f) is negative below 0.37 Hz). −∞ is the limit of negative resistances and is now refused like one, for bus impedances, grounding-conductor self impedances and voltage-source impedances: where the element is built, on the transient FFT grid and before the solve. Refusing rather than warning, because there is no value to continue with — +∞ would be an open circuit the formula does not describe — and because the same formula with a Carson term beside it was already refused (its approach to 0 Hz ends on a finite negative value). Positive infinity — the "nan" open end, 1/f, a capacitance at DC — stays an open circuit, and a network that does not list 0 Hz never evaluates the formula there and is not affected (a transient study always does). Migration: give the formula a finite DC value — let the frequency-dependent part vanish at 0 Hz (f*log(...), as in Carson's terms) or state the DC resistance as a term without f — or leave 0 Hz out of a stationary study. (D7)

    Added¶

    • run_outage_study(..., on_error="raise"|"record") and OutageStudyResult.failures, matching run_sweep.
    • ImportDefaults.switch_branch_type, switch_length_km and derive_phase_impedance (a phase_impedance_formula from r_ohm_per_km + I*x_ohm_per_km, deduplicated by formula) for the pandapower importer; preview_pandapower_import(..., defaults=...).
    • utils.impedance_calculator.compute_impedance_array and check_passive_impedance_array — the array path the transient solver uses; same results, same messages, without a ComplexNumber per bin.
    • Network.sources_reaching(fault_name), PathFinder.reaches, set_/get_pathfinder_max_paths, ElectricalNetwork.state_fingerprint().
    • A shared simple_network fixture in tests/conftest.py.
    • CI: the release workflow runs the test suite before it builds; pull requests run mkdocs build --strict and execute docs/examples/*.ipynb.
    • TransientStudy.solve(..., fft_block_bytes=None) bounds the memory of the FFT solver. Upper bound in bytes for one batch of dense admittance matrices, 256 MiB by default; the batch holds max(1, min(512, fft_block_bytes // (16 * n**2))) frequency bins for n active buses. A non-integer raises TypeError, a value ≤ 0 ValueError. (P8)
    • Diagnostic code TRANSIENT_PHASE_SPLIT (ModelAssumptionWarning, elements: the coupled branches). Raised by the state-space solver when the phase split of a meshed network depends on frequency — routes of different R/L ratio — so that a DC offset and harmonics are divided as at f_eval. (PH2)
    • gi.Database(path, *, migrate=True) — the SQLite store as an object. It owns its engine and session factory and offers the persistence operations as methods: save_bustype/load_bustypes/delete_bustype, the same for branch types, save_network/load_network/list_networks/ delete_network, needs_migration/migrate, session() for direct ORM work, close() and the context-manager protocol; ":memory:" gives a private in-memory database. Up to 0.6.0 the store lived in module globals: one database per process (a second file raised) and one session registry shared by every caller, which a GUI with two open projects or a server cannot use. Every method now runs in its own short-lived session; two databases on two files work from two threads at the same time, and one database works from several threads — operations on the same file are serialised by a lock shared by every Database of the process on that file. Without that lock, two threads saving networks that share a bus type failed with IntegrityError in 5 of 5 trials; with it, in none. A type a stored network still uses cannot be deleted. The new list/delete operations are also available as groundinsight.database.crud functions. (ARC2)
    • The JSON project file carries schema_version and groundinsight_version. Both are top-level keys in front of the model fields, so Network.model_validate_json still reads a project file and a 0.6.0 installation still opens one. load_network_from_json refuses a file of a newer schema with a ValueError that names both versions, instead of silently dropping what the newer release stored; files without the keys (0.6.0 and earlier) load unchanged. The current version is groundinsight.io.project_file.SCHEMA_VERSION = 1. (GUI1)
    • Network.stale_results() and Network.is_result_stale(fault) tell which stored results no longer match the network. run_fault stamps Result.input_digest, a digest of everything the result was computed from: the frequencies, every bus, branch and source as the solver reads them, and the definition of the result's own fault. The comparison is by content, so an undone edit makes a result current again, and outage_context, run_sweep and the rho searches -- which restore the network -- leave the flags as they found them; the result a study leaves behind computed under modified inputs (last outage scenario, last sweep point) is reported stale. Metadata (description, Fault.t_k_s/n_factor, a source's IEC 60909 characteristics) and other faults do not count. The digest survives JSON and the database (results are stored as JSON there; no migration); results without one -- written by an older version -- are never reported. Cost: 10 ms per check on a 1000-bus ring with 7 frequencies. (GUI3, F9)
    • Network.update_bus(name, **fields) and Network.update_branch(name, **fields). Every value is validated on a detached copy, bus references are checked and the impedances derived before anything is written -- all or nothing. Derived fields (impedance, self_impedance, …) and name are refused with an explanation. (GUI3, F9)
    • Network.remove_bus/remove_branch/remove_source/remove_fault. remove_bus refuses while a branch, source or fault refers to the bus and names every one of them; remove_fault also drops the stored result and the active flag; enumerated paths through a removed element are invalidated. Unknown names raise ValueError, like run_fault for an unknown fault. (GUI3, F9)
    • utils.validations.check_formula_symbols, BUS_FORMULA_SYMBOLS, BRANCH_FORMULA_SYMBOLS, FORMULA_CONSTANTS -- the symbol check of the type validators, usable by a formula editor. (USE2)
    • ResultReductionFactor.i_fault, u_earthing_group, z_earthing_group. i_fault is the denominator of value_current (the sum of the scaled source currents that reach the fault). The two group fields keep the earth-group mean as a diagnostic. (PH4, F4)
    • Fault.scaling_at(frequency), and scalings is optional. create_fault(..., scalings=None), scalings={} and Fault(...) without the argument all mean factor 1.0 at every frequency. scaling_at is the one place that applies this default. (PH6, USE4, F7)
    • ElectricalNetwork.earthing_admittance_matrix(freq) and ElectricalNetwork.thevenin_loop_admittances(freq). The first is the earthing network alone: electrodes and shields, without coupling and without Thevenin loop closures, from which Z_E is computed. The second returns the loop-closure stamps that the Y assembly and the earthing matrix share. BusResponse.fault_driving_point(z_bus, freq) returns Z_E for the electrode under test. (PH4)
    • Diagnostics with codes, collected in Result.diagnostics: ModelAssumptionWarning EARTH_GROUP_UNDEFINED, REDUCTION_FACTOR_UNDEFINED, EARTHING_IMPEDANCE_UNDEFINED (P9, PH4), PHASE_PROXY (PH3), THEVENIN_COUPLING (PH1), SOURCE_WITHOUT_PHASE_PATH (PH9) and THERMAL_DC_EXCLUDED (PH10); InputWarning SOURCE_FREQUENCY_GAP, SOURCE_FREQUENCY_OUTSIDE_NETWORK (USE3) and SCALINGS_INCOMPLETE (PH6); info LEGACY_EARTHING_DEFINITION (PH4).
    • BusResponse.z_fault_ideal. Where the electrode at the studied bus is the only one on the fault side, the earthing network without it floats and its open-network values (z_fault_open, z_fault_transfer, z_bus_open) do not exist. Z_E still exists for every electrode there, because all of the current leaves through it: fault_driving_point(z_bus) returns z_bus + z_fault_ideal, where z_fault_ideal is the driving point at the fault bus with an ideal electrode at the studied bus. With no electrode, it returns None. (PH4 follow-up)
    • gi.solve(network, fault) — a fault solve that writes nothing into its input. run_fault stores the result, activates the fault, may drop or rebuild the path set and attaches the assembled admittance system: right for a notebook, wrong for a GUI whose worker thread solves while the user interface reads the network, for an undo history, or for a study that promises to hand its input back. solve runs the unchanged run_fault pipeline on an overlay that shares the bus, branch and source objects (read only) and owns everything a solve writes, so its result is bit-identical to run_fault's — serialised comparison on a chain, a ring and a Thevenin network in both phase-current modes, and the closed form r = |(Z_s - Z_m)/(Z_s + Z_A + Z_B)| of a two-bus line to 4.4e-16 — and the network is unchanged afterwards: serialised form, stored results, active fault, path set, assembled system and private state, also when the solve raises. The overlay is a copy, not a construction, so the input's elements stay attached to the input and keep re-deriving on edits. The result carries the input digest run_fault would stamp: kept with network.results[fault] = result, it counts as current for stale_results() until the next edit. Not for two threads solving the same network object at once — the path caches are module-level. (ARC1)
    • gi.check_network(network, *, fault=None) — every problem of a network as data. Returns a list of Diagnostic records (code, severity, message, elements) and never raises; [] for a sound network. 25 codes, listed with their severity in groundinsight.checks.CHECK_CODES: invalid elements and frequencies, missing excitation, references to buses that do not exist, impedances the solver cannot invert (missing, NaN, not passive, formula errors), source frequency coverage, faults on unknown or inactive buses, partial scalings, faults no source reaches, isolated buses and earthing islands without a reference to earth. A branch end or a source on a bus that does not exist is something the solver drops without a word — on a four-bus ring with one branch pointing at a missing bus the maximum EPR became 239 V instead of 73 V; the editing API refuses such a reference, but a hand-edited project file or a script-filled network can carry one. The check is structural — no assembly, no solve — so a GUI can run it after every edit, and every severity is cross-checked against the solver: in 20 malformed networks each error is one on which run_fault raises or returns 0 V for a network that is not the one described. The codes SCALINGS_INCOMPLETE, SOURCE_FREQUENCY_GAP and SOURCE_FREQUENCY_OUTSIDE_NETWORK mean what they mean in Result.diagnostics. (GUI9)
    • Progress reports and cooperative cancellation in the five long-running studies. run_sweep, run_outage_study, find_max_rho_scaling, find_max_rho_f_scaling and TransientStudy.solve take progress(done, total, label), called after every unit of work — a sweep point, an outage scenario, one solve of a search, a batch of FFT bins (at most 512, fewer under a tight fft_block_bytes), a stage of the state-space solver — and should_cancel(), asked before every unit. A true answer raises the new gi.StudyCancelled (a RuntimeError with done and total) and puts the network back exactly as it was when the study was called: serialised form, stored results and their order, active fault, paths, assembled system. Python cannot stop a thread from outside, so until now a GUI or a server could only wait for a running study. The searches announce their total before the first solve — a log-bisection needs the same number of halvings wherever the threshold lies — and match it: 20 progress calls for 20 solves at the default settings, and the announced total equals n_scan + k for every tolerance and grid tried. Results with and without hooks are identical. (GUI5)
    • Networks as tables: gi.network_from_tables(...) and Network.to_tables(). Ten tables with a pinned schema (groundinsight.io.TABLE_SCHEMAS: column order and dtype; only frequencies, bus_types and buses are required), as Polars frames, CSV files or a directory of <table>.csv files; for a workbook, pl.read_excel(path, sheet_id=0) returns the dict of sheets network_from_tables takes (Polars needs its optional fastexcel for that). The tables hold input only: the network is built through the same Network.add_* path as create_bus & co., so every formula passes the formula guard and every impedance is evaluated from its type; results and paths are not exported. Network → tables → network is identical (model_dump_json without results) for four example networks and the shared test fixture, through frames and through CSV, and the rebuilt networks solve to identical results. Malformed tables raise one ValueError that lists every problem with table, row and column — missing or unknown columns (a typo such as lenght is not dropped silently), decimal commas, duplicate names, references to buses, types, sources or faults that do not exist, validation errors. Also groundinsight.io.network_to_tables. (USE6)
    • Network.res_fault(fault) — the key figures of a fault in one table. Fault current, EPR at the fault and the largest EPR with its bus, the EPR-based and the current-based reduction factor, the earth-return current I_E, the EN 50522 earthing voltage U_E and earthing impedance Z_E were spread over Network.faults, ResultBus, ResultReductionFactor and ResultGroundingImpedance, and every GUI tile, report template or script picked them out itself. res_fault returns one Polars frame with the pinned schema gi.RES_FAULT_SCHEMA: one row per network frequency and one RMS row (is_rms, frequency_Hz null), magnitudes and angles, and n_diagnostics, the number of records in Result.diagnostics, on every row. A value the result marks as undefined is null — r_current and I_E_A at a frequency without fault current, U_E/Z_E/I_F of a result stored before these fields existed; ratios, impedances and angles are null on the RMS row, which carries the stored RMS EPR and root sums of squares of I_F, I_E and U_E. It reads the stored result only and changes nothing: an unknown fault is a ValueError, a fault without stored result a RuntimeError that names run_fault and solve, and a stale result is reported as stored (stale_results() says so). Every column agrees with the result field it names and with an independent nodal solver to 1e-12 on a radial chain, a meshed cable/overhead-line ring and a network with two infeeds of different angle. (USE1, GUI6)
    • gi.PathfinderSettings and Network.pathfinder_settings — the limit and the memory of the path search belong to the network. Up to 0.6.0 the limit (set_pathfinder_max_paths) and the memory size (set_pathfinder_cache_size) were process-wide switches, and the memory was three module-level dictionaries shared by every network. The settings are runtime configuration and are not written to project files or the database. The limit error names the per-network fix. The head of this file states the scheme and the deprecation policy that replaces the compatibility promise SemVer used to carry.
    • Two reference cases were replaced by ones that can fail. en50522_chain checked U_E = 3*I_0 * Z_E * r with all three factors read out of one result — an identity the implementation closes by construction, so the case agreed to 1e-16 whatever the model did, and tripling every electrode current made the deviation smaller. The earth-group mean, which u_earthing/z_earthing used to report, came out 43 % below the fault-bus EPR and 45 % below the driving-point impedance on a homogeneous cable chain with the fault far from the infeed, the norm's ideal case. Taken as U_E into a touch-voltage assessment, that is unconservative. The chain closed only because Z_E was defined as U_E/I_E.     Fixed¶

    • The inverse searches no longer leave a stale nodal system behind (analysis/inverse_rho.py, analysis/inverse_rho_f.py). Both finally blocks restored rho, impedances, results, paths and the active fault but not network.electrical_network, so the network was left carrying the Y of the last bisection step next to the restored rho. bus_response read a negative driving-point impedance out of that pair, without error or warning. The pre-search object is put back (or None), and ElectricalNetwork carries a fingerprint of the model values it was assembled from so bus_response refuses a stale system by name.
    • BusResponse.evaluate reports the current Z_G definition. It computed Z_G = u_b/(r*I_F) — the definition 0.6.0 replaced — with the varied bus's voltage, a factor of 39 against run_fault. It is now Z_E = U_E/I_E of the bonded group, matching run_fault to 1e-9.
    • BusResponse.evaluate evaluates r_epr per electrode. It was carried through as an invariant, which it is only at the fault bus; away from it the factor moves with the electrode by 18 %. A third right-hand side of the same factorisation (the mutual-free injection) makes it exact for every electrode.
    • analyze_cuts decomposes the system that was solved. It assembled its own nodal matrix, which disagreed with the solver's in two places: a 0 Hz short, which the solver substitutes and the decomposition read as an open circuit (Z_dp 10 Ω against 2.5 Ω), and the Thévenin loop closure Y_src, which exists only in the solver's matrix and carried up to 23 % of the fault current out of the fault bus. The loop closure is reported as its own direction "source_loop"; kcl_residual falls from 22.5 % to 1e-16.
    • find_max_rho_scaling no longer assumes monotonicity. Where only part of the impedance formula carries rho, EPR(c) falls before it rises, and the bisection reported "no scaling factor satisfies the constraint" for limits a whole band of factors satisfies. A logarithmic pre-scan (monotonicity_grid, default 9) measures the shape first.
    • kappa and n are validated in the thermal checks. Both docstrings promised (1, 2] and (0, 1]; neither was enforced, and every out-of-range value failed in the unsafe direction.
    • The 0 Hz bin is no longer counted twice in I_th. It entered both the RMS and m; on the audit case [50 Hz] gave 1028 A and [0, 50 Hz] with 700 A of direct current gave 1255 A.
    • classify leaves a NaN unassessed instead of putting it in the highest band, where a failed sweep point was counted among the violations.
    • analyze_cuts explains an incomplete result instead of raising a bare KeyError, and CutAnalysis.to_polars() pins its schema so an unsolved analysis stacks with a solved one.

    • sweep([]) and a non-positive network conductance in worst_case_electrode raise ValueError instead of a polars error and a negative "worst case".

    • run_fault no longer enumerates every source-to-fault path in the default mode. phase_current_mode="auto" only needs to know which sources reach the fault, yet define_paths ran the exhaustive DFS on every call; a 6×6 grid of 36 buses spent 55–68 s on 1 262 816 paths while the solve itself took milliseconds. Network.sources_reaching(fault_name) answers the question with a breadth-first search, and the enumeration runs only for phase_current_mode="paths", the transient state-space solver and an explicit gi.create_paths(network). Results are bit-identical on every network where the old path was affordable; the 6×6 grid now solves in 0.09 s. PathFinder additionally caps the enumeration at set_pathfinder_max_paths() (default 100 000) with an error that names the bus pair and points at "auto". analysis/shortcircuit._sources_feeding keeps its old behaviour through the same reachability helper.

    • A frequency an element does not cover is an error, not an open circuit. _construct_Y_matrices skipped any bus or branch whose impedance dict lacked the frequency being solved, silently — extending network.frequencies in place and recomputing only the buses left the branches out of the 250 Hz bin and reported an EPR of 1000 V where 4.95 V was right. ElectricalNetwork now checks that every active element covers network.frequencies before assembling anything.
    • value_current with a source on the fault bus. I_fault was read as the net injection at the fault bus, which with a source there is I_src,F − ΣI_src rather than the fault current; the current-based reduction factor came out as 0.005 instead of 0.5. It is now Σ scaling·I_src over the sources that reach the fault.
    • run_sweep leaves the network as it found it, in every case. A point naming an unknown bus raised after the earlier buses had been overwritten, and because the return value of _apply was never bound, the finally block skipped the restore — with on_error="record" every later point was solved on the corrupted model. Names are validated before the first mutation, the snapshot is taken once per bus (R, L, C included, and a point overriding both bus_impedance and bus_rho on one bus can no longer save the overwritten table as the original), restore runs in reverse order, and the previously active fault keeps its cached result.
    • The FFT transient solver injects only sources that reach the fault, as the stationary solver does; a source on a galvanically separate bus used to add 1000 V at that bus and shift every other trace through the fault-bus term.
    • The state-space solver no longer reads its operating frequency from frequencies[0]. With 0 Hz first in the list the source inductance became L_src = 0 (a factor 680 in the first time step). solve() takes f_eval, defaulting to the smallest frequency above 0 Hz, and refuses a reactive Z_src at ω = 0.
    • Negative R_self, L_self, C_self, bus L and C are rejected by the state-space solver instead of being silently treated as absent, which made a branch with R_self = −0.5 lossless.
    • ComplexNumber == None is False, not a TypeError; the class is hashable; NumPy scalars (np.int64, np.complex64, …) work on either side of an operator; repr is a valid constructor call again.
    • Network.frequencies and every other model field validate on assignment (validate_assignment=True on Bus, Branch, Fault, Source, Network). apply_shortcircuit_characteristics could write kappa = 42 and a shortened t_k_s straight past the validators that promised to reject them, inflating i_p by 21 and I_adm by 7.7 — the unsafe direction — and left the network unserialisable. A rejected assignment is rolled back, because Pydantic writes the value before the model-level validators run.
    • Fault.scalings values are validated (finite, non-negative) — nan and inf went through and broke the JSON round-trip of the whole network.
    • The add_columns database migration works. The DDL it rendered for the eight NOT-NULL columns with Python-side defaults (position, active, source_type) had no DEFAULT clause, SQLite refused it, and because start_dbsession migrates before it binds, the file was unopenable. The column DDL is rendered with the declared default.
    • save_network no longer rewrites a shared type silently. Saving network B replaced the formula of a BusType network A also uses; A was then internally inconsistent (stored 1 Ω, formula 999 Ω) and every analysis that re-evaluates the formula — find_max_rho_scaling, run_sweep — switched to the wrong value. A changed formula on a type other networks reference is refused unless overwrite_types=True.
    • res_buses handles a missing ia_freq entry (None instead of an AttributeError), and the plot helpers release their figure when the drawing step raises (a bad yscale used to leak one figure per call).
    • The pandapower importer honours closed bus–bus switches when ImportDefaults.switch_branch_type is set, and otherwise warns and lists them in the preview together with transformers and impedances, which were dropped without a trace before — a station bonded to its neighbour by a switch came out isolated at 0 V. Bus voltage levels are matched with math.isclose instead of exact equality, so rounding noise from a CSV/DGS import no longer empties the whole import.
    • scripts/release.py runs git in the repository root, whatever the current directory, and refuses to touch the three version files when the target tag already exists.
    • Three doctests had gone stale (create_fault, create_source, the simulation/outage.py module example); the suite now runs the doctests (--doctest-modules) so they cannot rot again.
    • The state-space solver divides the phase current of a ring like the stationary solver. It took the phase factor of each branch from the enumerated source-to-fault paths as sign * parallel_coefficient (default 1.0), i.e. the legacy "paths" mode, which gives every route of a ring the full source current: 338.3 V at the fault of a symmetric four-bus ring in steady state against 166.6 V from run_fault (+103 %), without a warning. The split now comes from the same phase-network solve as phase_current_mode="auto", at f_eval, with 1 A per source; the complex split is folded into the coupling of each branch, R' + jωM' = (R_mut + jωM)·α, which makes the f_eval steady state exact for every topology (keeping only Re α put a cable/overhead-line ring 4.4 % low at the fault). Measured against run_fault: 3.6e-7 in the symmetric ring, 6.9e-8 in a chain (unchanged), 3.3e-7 in the mixed ring. Against an independent reference that integrates shield and phase conductors as states: 5.8e-7 of the peak for a homogeneous ring of unequal lengths under a fully offset fault current, 0.99 % for the mixed ring, where the solver says so (TRANSIENT_PHASE_SPLIT). The study no longer rebuilds network.paths and never touches network.active_fault. (PH2)
    • The FFT solver's coupling warning names the right direction. The TransientModelWarning for the mutual coupling the FFT solver does not evaluate said "expect a lower earth potential rise"; it is higher: 77.6 V against 49.2 V in the steady state of a coupled two-bus cable link, exactly 1/|1 − Z_m/Z_s| for one coupled branch, and +44 % to +101 % on the post-inception peak of a fully offset fault current in four networks. Without the coupling no induced share of the fault current returns through the shields, so the FFT answer is conservative at the fault bus and as the network maximum (higher in all of 600 random chains and meshes, while 6 % of the remote buses came out lower, which the message now says). The warning is emitted with code TRANSIENT_MODEL and every coupled branch as an element, and points at the caller's line. docs/transient.md claimed the same wrong direction. (PH-L1)
    • The FFT solver no longer needs gigabytes for mid-size networks. It assembled 512 frequency bins as one dense (512, n, n) block — 1.3 GB at 400 buses, 8.2 GB at 1000 — and kept the previous block alive while building the next, so the peak was about two blocks. The batch now follows the fft_block_bytes budget and is released before the next one: a 400-bus ring over 1001 bins peaks at 293 MB (tracemalloc, whole solve), a 100-bus ring at 89 MB instead of 167 MB with the default and at 10.7 MB with a 4 MiB budget. The spectra are bit-identical to the old batching, and the run time is unchanged (200 buses, interleaved median: 1.23 s old, 1.03 s new). (P8)
    • A solved network can be copied and pickled again. copy.deepcopy(net), net.model_copy(deep=True) and pickle.dumps(net) failed after run_fault with TypeError: cannot pickle 'SuperLU' object -- a regression of the LU reuse. The factor cache is dropped in copies (it is rebuilt when needed); the copied solver state refers to the copy, so bus_response works on it without a new solve, with the same numbers as the original and as a network built from scratch. (GUI2)
    • Creating a bus or branch is atomic. A formula that only fails when it is evaluated (negative resistance, NaN at one frequency, a complex R_self) left an element without impedances in the network, and the next run_fault failed on "carries no impedance" instead of on the formula. The impedances are now derived before the element is inserted; with overwrite=True the previous element stays. (ARC9)
    • create_fault(active=True) without a network raises a ValueError that says what is missing, instead of AttributeError on None. (ARC9)
    • A broken shield no longer opens the phase conductor. For a branch with a grounding conductor and an infinite self impedance ("nan", the documented broken shield) and no declared phase impedance, the phase-split proxy 1/Z_self was 0. That removed the phase conductor too. On a symmetric ring, the branch carried 0 A instead of half the current, and the fault EPR was 207.1 V instead of 342.0 V. Because the phase network then looked radial, the proxy note was suppressed as well. The branch now falls back to the length proxy (520.4 A / 541.3 A, 300.7 V), and PHASE_PROXY names it. (PH3)
    • Earth group, I_E and the reduction factors are no longer decided by rounding noise. Electrode currents of zero in exact arithmetic come out of the solver at about 1e-17 of the largest one, at an arbitrary angle, and joined an arbitrary group: 786 membership flips in 514 random networks between two kernels that otherwise agree to 1e-13. Without an electrode at the fault bus, I_E flipped sign and Z_G moved by a factor of 2.2. A fault bus at zero potential reported the quotient of two rounding errors as value (0.449 = 5.1e-14 V / 1.1e-13 V for a source behind a dead end). Currents up to 1e-9·max|I_a| now join no group. Without a fault-bus electrode, the group in phase with the fault-bus EPR feeds. When no current is dropped, the split is bit for bit the previous one. (P9, F14)
    • The earth-return split is O(n log n). It was quadratic: 11.2 s per frequency at 20 000 buses, now 9 ms (0.6 / 2.1 / 106 ms at 1 000 / 4 000 / 100 000). On 2 000 random phasor sets and a 4 000-bus set, the result equals that of the previous implementation with ==. (P3)
    • Carson mutual impedances no longer warn at 0 Hz. The resolution test of the DC limit compared the last step of the approach (10⁻⁷ → 10⁻⁸ Hz) with 10⁻⁶ of the value plus 10⁻¹² Ω. A real part without a constant term — the earth-return resistance π²·10⁻⁴·f of every Carson mutual impedance — moves by 90 % of its value per decade however small it is, so every such cable longer than 11.3 m warned "converges only slowly" in a network that lists 0 Hz, although its value there is π²·10⁻¹²·l Ω. A step that shrinks at least five-fold per decade now counts as resolved, since at most a quarter of it then remains to the limit: anything linear in f shrinks it ten-fold, f*log(1/f) 8.5-fold, while sqrt(f) (3.2-fold) and log(f) (not at all) are still reported, now with the measured step ratio in the message. The verdict no longer depends on the branch length, and the value used at 0 Hz is unchanged. The FFT transient solver was not affected; it evaluates self impedances only. (D7)
    • EARTHING_IMPEDANCE_UNDEFINED is decided by structure. Z_E (z_earthing, the grounding impedance) is None when no bus connected to the fault bus through shields has an electrode. That decision used to be left to the sparse solver, which caught only a fault bus standing alone. With one or three electrode-less buses behind the fault bus, the earthing matrix is singular only up to rounding, and z_earthing came out as about −4.5e15 or −3.6e15 Ω with no diagnostic. The reverse case was wrong too: a voltage source on a bus without an electrode reported Z_E = None for a fault side earthed at both ends, and the note blamed the fault bus. Now only the fault bus's own group is factorised, and the note names that group. bus_response uses the same rule for its earthing columns, and its check that another electrode remains now looks at the studied bus's group instead of the whole network. Checked against the closed forms of a series chain (Σ Z_s + Z_e) and a parallel pair (Z_F ∥ (Z_s + Z_B)), and against the reference solver of the tests, which finds the group by its own search and refuses a group without an electrode. (PH4, F4)
    • A group of buses with no path to earth is refused by the solve. run_fault refused a network in which no bus is earthed. A group of electrode-less buses joined by shields, for example a tower behind an overhead line without an earth wire, was solved to rounding noise: 2.18e18 V at the fault bus, with no warning. Every group of buses that the nodal matrix couples now needs a bus with an electrode. Otherwise run_fault raises the documented ValueError ("Singular admittance matrix … no path to reference earth"), naming the group. The check costs 0.5 ms per frequency on a 4000-bus ring and 2 ms on a 20 000-bus ring, less than 1 % of run_fault.
    • A purely inductive phase conductor at 0 Hz no longer makes run_fault raise ZeroDivisionError. A phase_impedance_formula such as j*2*pi*f*L*l is exactly zero at DC. The 0 Hz scan did not cover phase conductors, so a network whose only DC short was one crashed. Phase conductors now get the documented DC stand-in sqrt(eps)·Z_min with a DCLimitWarning that names them. Z_min remains the smallest impedance of the earthing network, so the earthing results of networks that already had a DC short are unchanged, bit for bit. Where every parallel route of the phase network is an ideal short at DC, the routes split as if all conductors had one and the same impedance; declare the DC resistance where that split matters.
    • run_sweep leaves the network exactly as found, as it always promised. It put the bus and branch parameters back but left the result and the assembled system of its last point in the network: on a four-bus ring, network.results["F"] read 52.2 V at the source bus after a sweep — the last point's value — instead of the 70.1 V of the restored network, and bus_response would have read the last point's matrices. Stored results and their order, active fault, path set and assembled system are now those of the moment the sweep was called, so the sweep's own fault is no longer reported by stale_results() afterwards. (GUI5)
    • find_max_rho_scaling and find_max_rho_f_scaling restore the network exactly. They put back the active fault, the stored result and the assembled system one by one, but re-inserted the result at the end of network.results: with results for F and F1 stored, the order became F1, F and the serialised network changed. (GUI5)
    • The pandapower import honours open line switches. A ring operated open at a line switch (net.switch row with et="l", closed=False) arrived closed: only bus-to-bus switches were evaluated, so the phase-conductor network got a mesh that does not exist in operation and the fault current divided over both halves of the ring — 643 A of 1000 A took the route through the open switch on a four-bus test ring. An open line switch interrupts the phase conductor of its line at that end; the cable screen is bonded to the station earth independently of the switch and stays connected at both ends. from_pandapower now imports such a line with its default_branch_type and phase_impedance_formula = "nan" (type <name>_phase_open): it carries no fault current, and its screen stays in the earthing network. It says so with the new InputWarning IMPORT_LINE_SWITCH_OPEN (severity info; elements: the branch and the switches). preview_pandapower_import marks the switch and its line line_switch_open, a closed line switch line_switch_closed and the switch of a line that is not imported line_not_imported. Switches at transformer terminals change nothing (transformers are not imported); an open bus-to-bus switch stays no connection. With one cable type on every line the EPR does not depend on the switch state — the coupling relief is 1 - Z_m/Z_s however the phase current divides — but the phase and screen currents do, and with them the thermal check; in a ring of mixed construction the EPR moves as well. The legacy phase_current_mode="paths" enumerates routes over every active branch and does not see an open phase conductor.
    • A fault on the bus of every source that feeds it now says why its reduction factors are empty. Source and fault put +I and -I on the same row, so nothing is injected into the earthing network: the EPR and the earth-return current are zero and both reduction factors are None by definition. The run was silent about it; it now records the info diagnostic FAULT_AT_FEEDING_BUS (elements: the fault and its bus) on the result. U_E is 0 V, Z_E remains the driving-point impedance.
    • run_outage_study(auto_parallel_coefficients=...) warns at its caller. The deprecated keyword was forwarded to run_fault, whose DeprecationWarning then pointed at a line inside the package, where Python's default filters hide it. The study resolves the alias itself; the old argument still wins when given.
    • Warning texts name limitations, not internal audit identifiers (THEVENIN_COUPLING).
    • res_fault names the bus of the largest EPR the same way on every platform. With a strict comparison, two buses with the same EPR magnitude -- both ends of a symmetric line -- were told apart by the last bit of the solution, which differs between the BLAS/LAPACK builds of Linux, macOS and Windows. Magnitudes within 1e-9 of the largest now count as a tie, and a tie names the fault bus if it is part of it, otherwise the first tied bus in result order.

    Security¶

    • The impedance formula guard is a whitelist and normalises Unicode (utils/validations.py). It compared raw token strings against an ASCII denylist, but CPython NFKC-normalises identifiers when it compiles the source sympy.lambdify generates: a fullwidth ｅval passed the guard and reached the builtin eval through create_bus, i.e. through every JSON and database load. Names must now be ASCII and NFKC-stable, only a fixed set of SymPy functions may be called (free symbols stay unrestricted — a user may name a parameter whatever they like, and a bare name can never become a call), only + - * / ** ( ) , are accepted as operators, and a power whose exponent is itself a power or a literal above 1000 is refused (the 10**10**9 denial of service). Formulas longer than 4096 characters are rejected up front. Nothing in the repository's docs, tests or notebooks is affected; a formula calling a function outside the list (factorial, besselj, …) now fails with a message that names the allowed set.
    • NetworkDB.frequencies is a JSON column, no longer a PickleType. Loading a database ran pickle.loads on the stored blob before any Pydantic validator saw a field, so a .db file from another hand was code execution — the very thing the formula guard exists to prevent. Files written before this release are converted by gi.migrate_database(...) (start_dbsession does it automatically) through a restrictive unpickler that resolves nothing but builtins.list/float/int and aborts before the first write when the blob names anything else.
    • pillow floor 13.0.0, without an upper bound (pyproject.toml). pillow = "^11.3.0" meant <12, while every fix lies at 12.1.1 or later. pip-audit lists 73 advisories for 11.3.0 and still 39 for 12.3.0; 13.0.0 is the first release without one. groundinsight never imports PIL — matplotlib does, and asks for pillow>=8 — so the declaration is a pure security floor, and it carries no upper bound: the cap is what kept the fixes out of reach of everyone installing groundinsight (SEC2).
    • Refreshed lock with the open Dependabot updates (#5, #6). The previous lock carried 171 known advisories in 16 packages (pillow 73, mistune 30, tornado 28, urllib3 7, …); the new one has none. numpy 2.1.3 → 2.4.6 (pandapower caps it below 2.5), scipy 1.17.1 → 1.18.1, pydantic 2.13.4 → 2.14.3, polars 1.16.0 → 1.44.2, sqlalchemy 2.0.36 → 2.1.8, matplotlib 3.10.9 → 3.11.2, pandapower 3.1.2 → 3.5.6, pytest 8.3.4 → 9.2.0, mkdocstrings 0.26.2 → 1.0.8. Installed from the lock, the suite passes on 3.12, 3.13 and 3.14 (REL2, SEC2). tornado 6.6 → 6.6.1 (development and documentation groups only) for CVE-2026-126347, published after the refresh and the first finding of the new audit job.
    • Dependency audit in CI (.github/workflows/audit.yml). On pushes and pull requests to main, weekly and on demand, scripts/audit_dependencies.py checks every version pinned in poetry.lock — all groups, extras and platforms — with pip-audit, and any known advisory fails the job. The ignore list .github/pip-audit-ignore.txt is empty; an entry needs a reason and an end date, and an expired entry fails the audit (SEC2).
    • Every GitHub Action is pinned to a commit SHA with its release as a comment, including pypa/gh-action-pypi-publish, which ran from the moving branch release/v1 inside the job that holds the PyPI OIDC token. Dependabot updates SHA and comment together (SEC3).
    • The workflow token is read-only by default. Every workflow declares permissions: contents: read; only the PyPI publish (id-token: write), the GitHub release and the docs deploy (contents: write) ask for more, each with a comment saying why. Checkouts in jobs that never push no longer leave the token in .git/config. zizmor: 50 findings (28 high, 7 medium) → 1 informational (SEC4).
    • bandit B608 in database/migration.py triaged and annotated. The four f-string SQL statements interpolate only module constants, caller literals and columns of the target schema the ORM just created; names read from the file being migrated are only used in membership tests. Each site carries # nosec B608 with that reason, and a test migrates a file with a hostile column and table name while recording every statement the module sends (SEC6).
    • Formula strings cannot make SymPy burn CPU any more. SymPy evaluates arithmetic on numbers exactly while it parses, and the guard only capped the literal exponent: <4080 digits>**999 cost 1.9 s per formula and a JSON with 20 such bus types 17.9 s to load; 9**(99999*99999) and floor(exp(10**12)) never returned, (0*f + 9)**(f - f + 4000000) cancelled its symbols (2.2 s), Max with 120 symbolic arguments took 6.6 s. The guard now bounds, before SymPy runs, the digits of number literals, every exponent (by the value it can reach), the size of every exact intermediate result, floor/ceiling and exp-like arguments, and the number of terms, calls and call arguments; each message names its limit. Measured: every case above is rejected in under 4 ms; the most expensive admitted formula (eight Max of three symbolic arguments) costs about 50 ms with cold caches. (SEC1)
    • The formula guard fails closed. A string Python's tokenizer cannot split was handed on to SymPy unchecked; it is now rejected by the guard ("could not be tokenized"), and so is a string that tokenizes but is no expression. The string is parsed inside parentheses, which accepts exactly the leading blanks and line breaks SymPy accepts. (SEC5)

    0.6.0 — 2026-09-01¶

    Added¶

    • Closed-form reference cases (gi.run_reference_cases). Six configurations whose answer is known in closed form, run through the ordinary public API and compared, with the derivation in each case's docstring rather than a quoted equation number. Measured deviations: the textbook r = |1 - Z_m/Z_s| under its own condition of negligible station electrodes (2e-6), the same line with finite earthing (5e-16), the EN 50522 chain (1e-16), the ladder-network input impedance Z_in = -Z'/2 + sqrt(Z'^2/4 + Z_e*Z') over 80 sections (3e-9), the potential decay u_n/u_0 = e^(-n*gamma) with gamma = arccosh(1 + Z'/(2*Z_e)) (3e-7), and the parallel decomposition at a station (1e-15). Each case states the boundary conditions its closed form needs, because a deviation more often means a condition was not met than that the model is wrong. Also run as tests, so a change that quietly breaks agreement cannot reach a release.

    • Characterising a location without knowing the electrode there (gi.bus_response). Adding an electrode is a rank-one change to the nodal matrix, so by Sherman-Morrison every nodal voltage is a Möbius function of its admittance. Two solves with the electrode removed therefore determine the response for every electrode — measured against genuine solves at Z_B from 0.05 Ω to 500 Ω and at 4+9j Ω, the closed form agrees to 3e-15 relative, on every bus and for the current-based reduction factor as well. BusResponse.extremes() gives the bracket: open (no electrode), ideal (Z_B = 0) and worst_passive. Both endpoints are exact limits rather than numerical stand-ins — the ideal electrode in particular, which the solver rejects outright because a zero impedance is not invertible. .evaluate(z) and .sweep([...]) cost no solve at all.

    • BusResponse.z_network is the site-independent number the analysis is built around: the driving-point impedance of everything except the local electrode. Verified identical whether the response was built from a network carrying a 0.5 Ω electrode or a 200 Ω one.
    • Z_dp = 1/(Y_B + 1/Z_net) exactly, so it runs monotonically from Z_net to zero. The largest magnitude over all passive electrodes is not at the open end but at the reactive resonance Y_B = -j·Im(1/Z_net), worth 0.1 % more in the verification network — small, but reported rather than assumed.
    • The closed form derives the invariance of the EPR-based reduction factor that the electrode sweep above measured: u_b(Y_B) = u_0b/(1 + Y_B·Z_net) holds with and without mutual coupling alike, so the quotient cancels. Algebra, not an accident.

    • The guard that the location is characterisable at all is structural, not a tolerance: at least one other bus must carry a finite grounding impedance once the electrode is removed. Leaving it to the linear solver is not enough — on the exactly singular case numpy returns a finite but meaningless -2.25e15 instead of raising, the same inconsistency the DC work found in scipy's splu.

    • Splitting the network at the fault location (gi.Cut, gi.analyze_cuts). A cut is a named set of branches, all incident to the fault bus; the analysis reports what each direction contributes.

      parallel impedance left --- fault location --- parallel impedance right

    Z_side comes from source-free current division: one ampere is injected at the fault bus with all sources and mutual injections removed, and the share leaving through each cut gives Z_side = u_fault / i_cut. The decomposition closes by construction — 1/Z_local + Σ 1/Z_side reproduces the driving-point impedance of the whole network, measured residual 1.2e-15 on a five-bus chain and on the same network with the ring closed. Isolating each side into its own sub-network would have been equivalent for a radial network and wrong in a ring, where removing one branch separates nothing and the far side comes out empty; that formulation was discarded before it shipped. From a solved fault the analysis additionally reports i_shield and current_share per direction (KCL at the fault bus closes to 2.4e-16), and where the directions are disjoint also i_earth, i_total and the side reduction factor. sides_are_disjoint says which case you are in; a passive spur gets r = None rather than a division by zero. Results as a typed CutAnalysis and as a long-format frame via .to_polars().

    • A second reduction factor, on a current basis (ResultReductionFactor.value_current). The existing EPR-based value is structurally blind to the impedance at the fault bus: both solves use the same Y, so changing Y_ff is a rank-1 update that cancels in the quotient. Measured: sweeping the fault-bus electrode over four decades leaves it at 0.500000 while Z_G moves by two orders of magnitude and the potential rise by a factor of fifty. A rho-f sensitivity study plotted against it would be a horizontal line. value_current is the share of the fault current that returned through earth rather than through the shields and does respond — 0.0414 → 0.00053 over the same sweep. Both are kept: value so earlier results stay reproducible and so the closed form r = |1 - Z_m/Z_s| keeps its meaning, value_current for sensitivity work. res_all_impedances() reports both.

    • Parameter sweeps (gi.run_sweep, gi.SweepPoint, gi.rho_f_points). Solve one fault once per parameter combination and stack the results into long-format frames that carry the parameters as ordinary columns (.buses(), .branches(), .impedances(), .cuts()). A point can override bus impedance tables, soil resistivity, the fault location or the harmonic scalings. rho_f_points builds the points from a catalogue of five-parameter rho-f vectors — the form groundfield exports — and rejects a vector that gives Re(Z) <= 0 where it is built rather than three layers down in the solver, because an unconstrained least-squares fit can land there. Overrides are undone in a finally block, so a failing point leaves neither the network nor the remaining points contaminated; failures are recorded per point and the sweep carries on (on_error="raise" for the strict variant).

    • Statistics and classification (gi.summarize, gi.classify). Count, spread, named quantiles and extremes for any numeric column, grouped or not; and a class column that bins a quantity into user-supplied bands, closed on the right so a value exactly on a limit stays in the lower band. There is deliberately no built-in table of admissible values — touch-voltage limits depend on the clearing time, the standard edition and the assumed additional resistances, and a constant baked in here would be carried into a result without ever being checked. The edges come from the caller, who can cite them. summarize names the frequency_Hz-is-a-string trap in its error message rather than just refusing.

    • BranchType.phase_impedance_formula (optional, symbols f, rho, l) and the evaluated Branch.phase_impedance, mirrored in SQLite and JSON. It describes the phase conductor -- the faulted conductor whose current induces the longitudinal EMF on the shield -- and is what the automatic phase-current distribution solves on. It never enters the nodal admittance matrix and is therefore not passivity-checked. Where it is absent and the phase network around the fault carries a cycle, the solve falls back to 1/Z_self (with a grounding conductor) or 1/length (without) and warns once per solve, naming the branches: those two quantities are not comparable, so the split between routes of different construction is a heuristic rather than a physical result. On a ring whose two legs differ by a factor of ten in phase impedance the declared formula divides the current 909.1 A / 90.9 A, as it should.

    Changed¶

    • Breaking: ResultGroundingImpedance.value is now Z_E in the EN 50522 sense — the earthing voltage of the bonded earthing system over the current it passes into the soil — instead of u_EPR / (r_coupling * I_F). The old expression mixed the coupling ratio into an impedance: on the verification feeder it reported 0.219 Ω where the earthing system actually presents 3.298 Ω, a factor of fifteen, the same one that separates the two reduction factors. With the new definition the norm's chain U_E = 3*I_0 * Z_E * r closes on the reported value itself. Every ingredient of the old expression is still in the result (ResultBus.uepr, ResultReductionFactor.value, the source currents), so an earlier number can be reconstructed where a comparison needs it.

    • run_outage_study forwards phase_current_mode and defaults it to "auto" as well -- an outage study is precisely where a ring turns into a chain and back, so the modelling assumption must not change underneath it.

    • Breaking (behaviour, meshed networks only): the default phase-current determination moved from the path-based scheme to the phase-network solve. A meshed network solved with the previous default returns different -- and now non-degenerate -- numbers. Radial networks are unchanged. Branch.parallel_coefficient is ignored in "auto" mode; it still applies in "paths".

    Fixed¶

    • The current-based reduction factor summed the wrong thing. I_E is the total earth-return current, and in a cable network with continuous shields the stations are bonded to one another, so the current spreads along the shields and leaks into the soil at every bonded station — the earthing current is distributed by construction. The first implementation summed the electrode currents of every bus except the faulted one, which by Kirchhoff (Σ I_a = 0 over the whole network) is identically the electrode current of the faulted station alone. Measured on a six-station feeder at 50 Hz:
    fault position as shipped first correct factor
    mid-feeder 0.010947 0.032385 2.96×
    one station from the infeed 0.001955 0.009138 4.67×
    far end 0.026939 0.048327 1.79×

    The group is not found from the potential profile: the crossing falls between stations rather than on one, and with the fault near the infeed |EPR| runs 91.4, 19.6, 18.7, 18.1, 17.7, 17.5 V — no crossing anywhere. What is unambiguous per bus is the direction of its electrode current, so the split is made in the complex plane over the half-plane whose sum is largest: threshold-free, no angle nominated, and it reduces to the obvious answer when the two groups are cleanly opposed. New groundinsight.utils.earth_current with split_earth_currents; ResultReductionFactor gains i_earth (the ampere value) and earth_buses (the group) so the split is inspectable, and a separation diagnostic is logged when the phasors are spread in angle. Both groups carry the same sum with opposite signs, so |I_E| is independent of which is named which; the fault bus anchors the naming. BusResponse uses the same definition, and there the electrode under test contributes its own current rather than the one the response happened to be built with.

    • The EN 50522 chain U_E = 3*I_0 * Z_E * r now closes in the result. ResultReductionFactor gains u_earthing (the earthing voltage of the bonded group, the mean potential weighted by each station's electrode current) and z_earthing (Z_E = U_E / I_E). All three routes to r — the current ratio |I_E|/|3I_0|, the voltage route U_E/(Z_E*3I_0), and the reported value_current — agree to machine precision across three decades of electrode impedance, which settles that value_current is the norm's reduction factor. Rearranging the norm to U_E(r)/U_E(r=1) = r is correct and its reference case is r = 1, meaning the whole fault current through Z_E: 3298 V on the verification feeder, against the 214 V that removing only the mutual coupling gives while the shield stays in place as a metallic return. The ratio of those two reference voltages is exactly the ratio of the two factors and nothing else. Two further things are worth knowing and are pinned by tests: Z_E is not the electrodes in parallel — the shield sections between the bonded stations add to it, 3.30 Ω against 2.50 Ω — and where the group is not actually equipotential the lumped U_E is a weighted average of different voltages, which is reported at INFO.

    • The two reduction factors are now documented as the different quantities they are, and the gap between them is reported. They are not two computations of one number: for a route with shield impedance Z_s, mutual impedance Z_m and station electrodes summing to Z_E, r_coupling = (Z_s-Z_m)/Z_s against r_current = (Z_s-Z_m)/(Z_s+Z_E), so their ratio is the current divider Z_s/(Z_s+Z_E) and nothing else. ResultReductionFactor.value is the ideally bonded limit — the tabulated cable property 1 - Z_m/Z_s, blind to the station earths by construction — while value_current is what this earthing system actually passes into the soil. The divider is logged at INFO where it drops below 0.5 — a wide gap is a property of the network rather than a defect, and with ordinary station electrodes it is the normal case.

    • compute_reduction_factors raised a bare KeyError instead of skipping. Its except LinAlgError: continue never wrote u_vectors_no_mutual[freq], and the loop straight after it dereferenced that key. A frequency whose no-mutual solve fails is now reported as None.

    • A ring, a mesh or a second parallel cable no longer collapses the result. The phase current per branch used to be handed out by walking the enumerated source-to-fault paths and giving every branch on any path the full source current, scaled by Branch.parallel_coefficient. Without a cycle that is exact -- there is one route and it carries everything. With a cycle the same current was handed out more than once instead of being divided, and the mutual injections it drives were multiplied with it. Measured on a symmetric ring (S-A-F / S-B-F, Z_self = (0.1+0.2j)*l, Z_mutual = (0.05+0.1j)*l, 1000 A) at the default coefficient of 1.0, the two contributions cancelled the source exactly and the network solved to EPR = 0 V, r = 0, Z_G = None across every bus -- announced with nothing louder than a log line. Two identical cables between the same two buses did the same thing. In a mesh the outcome additionally depended on the order the branches had been declared in, because "the first path a branch appears on fixes its direction": the same topology gave Z_G = -0.00272 + 0.11121j or +0.00272 - 0.11121j depending on insertion order.

    • run_fault gained phase_current_mode, defaulting to "auto". The new default solves a reduced phase-conductor network per source -- fault bus as reference, source current injected at the source bus -- and reads the branch phase currents off that solution. On the ring above it lands on EPR = 55.6208 V, r = 0.5, Z_G = 0.0507 + 0.0990j, which is bit-for-bit the result a user previously had to reach by setting parallel_coefficient = 0.5 on every branch by hand. Radial networks are unaffected: both modes agree to 1e-9 there, so existing studies keep their numbers. phase_current_mode="paths" restores the old behaviour verbatim, including the collapse, so pre-0.6 studies stay reproducible.

    • An island no longer discards a whole source contribution in silence. The phase-network solve pinned the fault bus over the whole bus index range, which leaves any other island without a reference node and makes the reduced matrix singular; the resulting LinAlgError was caught and the source skipped, removing all mutual coupling -- r jumped from 0.5 to 1.0 and the EPR doubled, with no warning. This hit run_outage_study(auto_parallel_coefficients=True) directly, since an outage disables named elements and leaves orphaned buses active. The solve is now restricted to the fault bus's own galvanic component, a source with no phase-conductor route to the fault is reported by name, and a genuinely singular restricted system raises with the branch types to check.

    • _warning_parallel_coeffcient no longer false-alarms. It counted paths across all faults, so a strictly radial network that merely carried two fault definitions triggered the meshed-network warning. The check is now scoped to the active fault and to a single source reaching it over more than one path -- the only configuration in which the path-based mode multiplies the current.

    0.5.0 — 2026-07-31¶

    This release makes direct current a real operating point, adds transient simulation with two independent solver paths, and adds the equipment-integrity side of a grounding study — thermal limits for the conductor between two buses and for the two grounding elements at a bus — next to the potential rise that was there before. It also carries fourteen audit passes worth of correctness work. The full measurement protocol for every finding (reproduction, negative control, and mutation testing where the change touched drawing or matrix-assembly code) is kept out of these notes and lives in docs/audit-log.md.

    Breaking changes are marked in Changed. Databases written by an earlier release are converted automatically — see Added.

    Added¶

    • f = 0 Hz is a frequency, not a special case. A study at zero frequency used to raise, and the documented workaround was to enter f = 0.1 Hz instead. Both solvers now evaluate the DC bin, and the three singularities a formula string can hit there are told apart rather than lumped together: Carson's removable 0·∞ resolves to its limit, the capacitive 1/(jωC) stays an infinite open circuit, and a genuine failure (√ρ with negative ρ, a NaN) still raises. An impedance that becomes a true short circuit at DC is replaced by a substitute impedance sized from the network's own smallest impedance (√eps · |Z|min) and reported through the new gi.DCLimitWarning; docs/concepts.md explains when to merge the two buses instead. New public helpers is_short_circuit(z) and dc_substitute_impedance(...) in groundinsight.utils.impedance_calculator. What the old workaround cost, measured: for the common (0.25 + j*0.6)*l spelling it reported 718.54 V instead of 456.62 V and Z_G = 2.87 Ω instead of 1.82 Ω, and the error did not shrink with the frequency.
    • Transient simulation — the new groundinsight.simulation.transient sub-module, with two solver paths behind one contract: gi.TransientStudy(network, fault_name) plus set_source_waveform, set_observation(buses=, branches=) and solve(t_end, dt, solver=), returning gi.ResultTransient (time_s, epr_t, i_branch_t, source_t, to_polars()). Switching solver paths is a one-line change.
    • solver="fft" — frequency-domain superposition of a user waveform.
    • solver="state_space" — modified nodal analysis assembled as dx/dt = A·x + B·u and integrated with scipy.signal.lsim. Resolves the true ring-down that the FFT path cannot, and supports bus capacitance, automatic pi-section lumping of branch shunt capacitance, voltage sources (Norton reduction for a resistive loop, an explicit inductor state for L_src > 0) and Carson-style mutual coupling.
    • Lumped RLC parameterisation — optional R_formula, L_formula, C_formula on BusType and R_self_formula, L_self_formula, C_self_formula, R_mutual_formula, M_mutual_formula on BranchType, evaluated into real Dict[float, float] fields on Bus and Branch by the new compute_real_value helper. All default to None, so the frequency-domain path and existing networks are unaffected; the duplication against impedance_formula is intentional so the stationary and transient parameterisations can be maintained independently.
    • gi.waveforms — step, sinusoidal_with_dc_offset and damped_oscillation factory functions returning vectorised time-domain callables, plus the plotting helpers gi.plot_epr_transient and gi.plot_branch_current_transient.
    • Thermal limit check for conductors (roadmap F1). gi.check_conductor_limits(network, fault, t_k, *, kappa=/r_to_x=, n=, f=) compares every grounding branch's thermally equivalent short-time current against its adiabatic limit and returns a long-format Polars frame. I_th = I_rms·√(m + n) (IEC 60909-0) is applied to the superposed AC RMS shield current — linear superposition first, the non-linear factor on the aggregate — against I_adm = k·S/√t_k (IEC 60949). BranchType gains conductor_material, cross_section_mm2, theta_initial_C and theta_final_C; new helpers gi.iec60949_k, gi.iec60909_m, gi.kappa_from_r_to_x and the catalog gi.IEC60949_MATERIALS, verified against the published k tables (Cu/XLPE 143, Cu/PVC 115, Al/XLPE 94).
    • Thermal limit check for nodes (roadmap F4). EN 50522 and IEC 61936-1 size the earthing conductor and the earth electrode for different currents, and the solver did not expose the first of them at all — in the verification network the two differ by a factor of 41. gi.check_node_limits(...) assesses both per bus and reports every bus, leaving within_limit = None where the BusType declares nothing. ResultBus.i_inj / i_inj_freq report the source-only nodal injection — the current a lumped earthing conductor carries into the system — which is not ResultBus.ia = u_EPR / Z_B, the share dissipated into the soil through the electrode. BusType gains five fields per element (material, cross_section_mm2, theta_initial_C, theta_final_C, current_split). current_split ∈ (0, 1] is a declared factor, not a derived one: the split depends on geometry the nodal model does not carry. gi.final_temperature(material, covering) and gi.FINAL_TEMPERATURES name their source per entry and raise rather than return a plausible-looking number for an entry they cannot cite.
    • IEC 60909 short-circuit characteristics from a solved pandapower case (roadmap F2/F3). gi.read_shortcircuit_results(net_pp, ...) reads a calc_sc result as 60909 quantities in amperes, gi.apply_shortcircuit_characteristics(...) writes them onto the model and returns an audit frame including the previous values, and gi.resolve_fault_sc_characteristics(...) reduces several infeeds to one effective kappa (current-weighted by default, reproducing the sum of the individual peaks to 1.6e-16; aggregation="max" for the conservative variant). Source gains i_k_a, r_to_x, kappa, Fault gains t_k_s, n_factor — metadata that never enters the linear solve. Two deliberate deviations from pandapower, both pinned by tests: ip_ka and ith_ka are derived here because pandapower returns NaN for the 1ph case that matters for grounding, and I_th is always recomputed because pandapower sets m = 0 for kappa > 1.99 where the analytic limit is m = 2, which under-estimates the thermal stress. The R/X driving kappa is that of the earth-fault loop 2·Z1 + Z0, not R1/X1.
    • Databases written by an older release are converted, not rejected. gi.migrate_database(path) converts a file written by the name-keyed schema to the current one and gi.needs_migration(path) classifies a file without touching it; gi.start_dbsession() migrates automatically (migrate=False restores the previous behaviour, which now raises a RuntimeError naming the tool and your file). The original is copied to <path>.bak first and an existing backup is never overwritten; the conversion is written to a temporary sibling and moved in with os.replace, so an interruption leaves either the old file or the new one. Every converted network is loaded back before the swap, because a structurally valid file is not necessarily a usable one. gi.MigrationReport names what could not be recovered — shared elements, paths whose segment order does not form a connected chain, orphans, dangling memberships, defaulted cells — instead of quietly guessing, and a missing length or scalings aborts the migration rather than being invented.
    • The plotting helpers accept ax= and close=. ax= draws into an axis you already have, which is what makes a base case and an outage case comparable in one figure; close=True unregisters the figure the call created, so a parameter sweep no longer accumulates figures until matplotlib warns at twenty. Both are keyword-only and appended behind a *, so the historical positional signature is unaffected.

    Changed¶

    • Breaking: the SQLite schema keys elements per network. Buses, branches, faults, sources and paths carry the composite primary key (network_name, name); the five network_* association tables are gone, the relationships are ordinary one-to-many, and path_segments was promoted to a mapped PathSegmentDB keyed (network_name, path_name, position). Two networks in one file that both contained a bus called "A" previously shared a single row, so saving the second silently overwrote the first one's impedance. Element order now survives the round-trip — before, the load order was whatever SQLite returned, which reordered the Y-matrix assembly and changed the LU factorisation in the last bits; a save/load/re-solve is now bit-identical.
    • Breaking: a zero, a sub-invertible or a negative-real-part impedance raises ValueError. Z = 0 was assembled as an open circuit — the exact opposite of the ideal earth it is written to mean — and an impedance too small to invert put inf on the diagonal and NaN in the result. The rule covers bus grounding impedances, branch self impedances where grounding_conductor=True, and Source.source_impedance, and it runs again immediately before the matrix is assembled. Deliberately out of scope: mutual impedances (Z_mutual = 0 is the ordinary way to say "no coupling"), non-grounding branches, inactive elements, frequencies outside network.frequencies, and inf, which remains the documented open-end sentinel. Replace a deliberate 0.0 with a small finite value — 1e-6 Ω is seven digits of the ideal limit in a 1 Ω network and, unlike 0.0, actually behaves like one.
    • Breaking: create_paths — and therefore run_fault — rejects a network with no sources or no faults, which previously produced a complete, structurally valid all-zero result. The check is on the collections being empty, never on the resulting path count: an outage scenario that islands the fault bus still runs and still legitimately returns all zeros.
    • Breaking: create_network_assistant validates number_buses and branch_length. A line of n buses has n − 1 branches; passing n lengths silently dropped the last one and passing too few raised a bare IndexError. A scalar branch_length=1.0 now gets a message instead of TypeError: 'float' object is not subscriptable.
    • Breaking: max_iter must be an int >= 1 in find_max_rho_scaling and find_max_rho_f_scaling. max_iter=60.0 was never harmless — the loop condition rounds up, so 2.7 meant three steps, and a cap that does not mean what it says is worse than no cap.
    • Breaking: the plotting helpers reject two argument combinations and an unusable figsize. ax= with figsize= and ax= with close=True both raise ValueError, because the figure belongs to the caller in that case. A figsize that cannot be used raises instead of being swapped for the default: matplotlib accepts figsize=(0, 0) at creation and only fails when the figure is drawn, which pointed the traceback at savefig rather than at the call responsible.
    • Final temperatures now have two regimes with one source each. The catalogue previously mixed the National Grid Earthing Technical Specification and IEC 60364-5-54 in one table. Uninsulated conductors follow EN 50522 Table 2 — 300 °C for bare copper, aluminium, steel and galvanised steel, 150 °C for tinned copper, whose tin coating melts at 231.9 °C. Insulated conductors are capped by their insulation, not by the metal: IEC 60364-5-54 Table 54.2 gives 160 °C for PVC and 250 °C for XLPE and EPR, for every conductor material, because the insulation fails first. IEC60949_MATERIALS["Steel"]["theta_final_default_C"] is lowered from 400 °C to 300 °C: θ_f enters the IEC 60949 material constant k under a logarithm, so the old default produced a larger k and permitted more current — the unsafe direction for a limit check. Pass theta_final_C=400.0 explicitly to reproduce earlier studies. "PE" is deliberately not tabulated and raises, as do physically impossible pairings such as ("Al", "tinned").
    • A finite reactance at 0 Hz falls back to the real part, with a warning. (0.25 + j·0.6)·l reports 0.6 Ω of reactance at every frequency, and at DC that is a statement about nothing — a reactance either vanishes or is infinite. The warning quotes the length-invariant X/R ratio rather than the two values, so Python's default filter collapses a hundred-branch network into one line, and it names the remedy: write the reactance as j*2*pi*f*L and it vanishes at DC by itself. The fallback is off for R/L/C parameters, which are real at every frequency by contract. Correspondingly, Z = 0 and a non-invertible |Z| are accepted at 0 Hz and rejected above it — an inductance really is a short circuit at DC and really is not one at 50 Hz — while a negative real part stays rejected at every frequency, because a passive element is passive at DC too.
    • find_max_rho_scaling and find_max_rho_f_scaling return four new keys. status is one of "converged", "bracket_within_tol_on_entry", "bracket_fully_admissible" or "max_iter_reached", converged is True for the first two, c_bracket is the interval that provably contains the threshold, and bracket_rel_width is its relative width. For a fully admissible bracket the interval is (c_hi, inf), which makes "widen c_bounds" machine-readable. Every previous key keeps its name and meaning, so code reading c_max still works — it now has a way to find out whether that number is a maximum.
    • An unsolvable nodal system is diagnosed instead of being reported as a singular matrix. A NaN in Y or in the injection vector is now a computation error naming the buses and branches whose stored impedance is NaN, with self and mutual told apart, rather than reaching SciPy and coming back as "singular matrix" — which sends the engineer looking for a topology error. "No path to reference earth" lists which buses were examined and why each failed, grouped into Z = 0, infinite, NaN and no value stored at that frequency, truncated after five names with the total reported. The word Singular is kept at the front for callers matching on it.

    Fixed¶

    • Security: an impedance or RLC formula string was an arbitrary-code execution vector, and mkdocs.yml loaded polyfill.io, a domain that had changed hands and was serving malicious redirects. Both closed.
    • Formula evaluation. A formula that merely contained the letters nan (nan_factor, tanh) became an open circuit. A parameter whose name collides with one of SymPy's ~680 exported names was shadowed, and params={"I": ...} was silently overwritten with the imaginary unit. Every formula whose argument goes negative — the common √(1 − x) fit outside its range — collapsed to NaN, which was then passed on as if it were a number, into ComplexNumber, into Y, and out the far side as a result. compute_real_value(..., name=...) now actually reaches the caller, so two BranchType fields sharing an expression no longer produce two byte-identical messages.
    • Paths and topology. The path set went stale after a fault or a source was added following the first run_fault: the new element was never given paths, which made find_max_rho_scaling over-estimate the admissible soil resistivity. run_fault now rebuilds when the active topology changed, and Network.invalidate_paths() is an atomic rebind scoped to the calling network rather than a clear of the global cache. Two topology fingerprints collapsed parallel branches into one key, so two structurally different networks hashed alike. Network.define_paths no longer shadows (source, fault) pairs that share a source.
    • Transient solvers. With network.paths empty or stale the state-space path dropped the entire Carson coupling silently, and a branch shared by two parallel paths of one source received the coupling twice. Branch currents from the state-space solver were inverted relative to compute_branch_currents and the FFT solver; both now follow i_branch = (v_to − v_from) · Y_self, so the two traces sit on top of each other for the forced response. The source waveform is treated as the literal injection instead of being rescaled.
    • Persistence. save_network committed its delete-then-insert in two steps, so an interruption could leave a half-written network on disk, and it wrote raw type rows instead of merging them. Network.results, Fault.active and open-end inf values now survive the JSON and SQLite round-trips. Inconsistent path segments are rejected before anything is written.
    • pandapower import. calc_sc's tk_s=1.0 signature default was read as the protection's actual clearing time. Three pl.DataFrame(...) sites relied on polars inferring a schema from the first row. A missing line length was silently replaced by 1.0 km — a fabricated length changes the earth potential rise with nothing in the output to show it was invented — and zero or negative lengths are now rejected. Duplicate line names no longer abort the import.
    • Results that looked like answers. A frequency that was never computed was plotted as a bar of height zero, indistinguishable from a computed zero. The relative delta of an outage study divided by the reference value without guarding a zero reference. check_conductor_limits and check_node_limits reported "no violations" on a result that was only half built, and an element carrying just one half of its thermal data was skipped without a word. str() on ResultReductionFactor and ResultGroundingImpedance raised AttributeError. An unresolvable bus or branch type surfaced as an AttributeError from deep inside the solver, and two documented ValueErrors were never raised at all.
    • The inverse-ρ searches. iterations == 0 meant three different things; exhausting max_iter was silent; tol_rel and max_iter were unvalidated; a NaN EPR limit passed the positivity guard because nan <= 0 is False; and c_bounds=(1e-3, inf) passed the ordering check. The shared checks and the report builder now live in analysis/_bisection.py so the two searches cannot drift apart. The routines also restore network state instead of leaving the scaling they last tried in place.
    • A single un-earthed tower no longer fails the whole network, and a genuinely singular or floating network raises a clear ValueError naming the cause instead of surfacing as a SciPy factorisation error.
    • Session and cache handling. _set_session is the single source of truth for the module globals; start_dbsession is hardened against a second call and close_dbsession tears down all three globals; set_log_level is handler-idempotent across repeated calls; the pathfinder caches are bounded LRUs that no longer key on id(network); outage_context clears them and is re-entrant. Network.frequencies is validated at construction and warns on a non-monotonic order. gi.set_active_fault(network, fault_name, keep_results=False) is available at the top level, and __all__ lists every public helper.

    • groundinsight.analysis sub-package — new home for higher-level analysis routines on top of run_fault. First inhabitant: an inverse determination of the maximum admissible bus rho-f characteristic.
    • find_max_rho_scaling (groundinsight.analysis.inverse_rho) — given an existing network, an active fault and a set of selected buses, log-bisects the largest uniform scaling factor c of those buses' specific_earth_resistance such that the RMS earth potential rise at the fault bus stays at or below a user-supplied limit u_max. Returns c_max, the EPR at c_max, the per-bus rho_max = c_max * rho_0, and the iteration count. Honours every user-defined BusType.impedance_formula, restores the original rho values via a finally block (success or failure). Re-exported on the package as gi.find_max_rho_scaling.
    • rho-f model inversion (groundinsight.analysis.inverse_rho_f) — foundation layer for inverting the canonical rho-f bus model Z(rho, f) = k1*rho + (k2+jk3)*f + (k4+jk5)*rho*f (the same form fitted by groundmeas.services.analytics.rho_f_model). Two public entry points, both re-exported on the package:
    • evaluate_max_epr_under_k(network, bus_names, k, *, fault_scalings=None, run_fault_kwargs=None) -> Dict[str, float] — overwrites every selected bus' impedance with the rho-f form for the given k = (k1..k5), sweeps each bus once as the active fault (reusing pre-existing faults at swept buses, otherwise creating temporary ones with fault_scalings), runs run_fault and returns the per-bus RMS EPR. Restores bus impedances, drops temporary faults, and rebuilds the path cache in a finally block.
    • find_max_rho_f_scaling(network, bus_names, u_limit, k_ref, *, c_bounds=(1e-3, 1e3), tol_rel=1e-3, max_iter=60, ...) — log-bisects the largest scaling factor c such that k = c * k_ref keeps the maximum RMS EPR across the swept buses at or below u_limit. Returns c_max, k_max = c_max * k_ref, the achieved max EPR and the per-bus EPR breakdown at c_max.
    • select_rho_f_from_catalog(network, bus_names, u_limit, candidates, *, fault_scalings=None, run_fault_kwargs=None, sort_by="max_epr_asc") — evaluates every entry of a curated catalog {name: (k1..k5)} and returns a Polars DataFrame with columns name, k1..k5, max_epr_rms_V, admissible (bool) and one epr_<bus>_V per swept bus. Default sort puts admissible candidates first, ordered by ascending EPR margin. Useful for picking the feasible soil/curve from a hand-curated list (e.g. groundmeas fits per soil class). A full Pareto front in ℝ⁵ remains a roadmap item and will land as a separate find_max_rho_f_pareto_front on top of the same helper.
    • notebooks/07_inverse_rho_f.ipynb — step-by-step demonstration of the three rho-f inversion entry points on a small three-bus MV line with frequency-dependent excitation.

    Roadmap¶

    Feature ideas and scheduled work. Graduate an item from here into the appropriate category of [Unreleased] once it is implemented and ready for release.

    Scope boundary¶

    groundinsight is a reduced-model solver for networked grounding systems: nodal admittance assembly in the frequency domain, driven by formula-based or tabulated impedance values. PDE/FEM field computation is an explicit non-goal — it belongs in a companion package groundfield that depends on groundinsight and produces reduced models (impedance tables, multi-port Z matrices, Network objects) which groundinsight consumes. The roadmap below is organised around that split: the "bridge" items below define the data-exchange surface between the two packages.

    Near term — bridge to groundfield¶

    These items define the data-exchange surface between field-level computations in groundfield and circuit-level solves in groundinsight. The first work package (AP 1) of the dissertation drives the priority.

    • Two-layer SoilModel — dedicated Pydantic model with rho_1, rho_2 and h_12 fields, recognised as symbols by the formula evaluator (rho1, rho2, h in utils/impedance_calculator.py and utils/validations.py). Backwards compatible: single-layer behaviour when only rho is given. Shared type with groundfield.
    • ImpedanceTable as an alternative to formula strings — accept Dict[Tuple[rho, f], ComplexNumber] or a user callback on BusType / BranchType alongside the existing SymPy formula path. Primary use case: ingest FEM-computed impedances from groundfield without pressing them into a closed-form formula.
    • Multi-port impedance matrix export (Z_ON) — function Network.impedance_matrix(f) returning the full multi-port Z matrix of the grounding subsystem for a chosen set of terminal buses. This is the return channel: a field solution in groundfield can be reduced to a multi-port representation that groundinsight produces or consumes through the same interface.
    • Parametric TN-Ortsnetz builder (new module src/groundinsight/simulation/tn_builder.py) — constructs a Network from structural parameters (number of family houses, small / medium commercial connections, cable-distributor quota, topology class). Directly supports the AP 1 parameter grid (5 / 10 / 30 / 80 / 200 × …).
    • Parameter-sweep runner (src/groundinsight/simulation/sweep.py) — sweeps over rho, soil-layer thickness, network size, fault location and frequency; returns a long-format Polars DataFrame. Matches the AP 1 investigation programme.
    • Touch-voltage result type — ResultTouchVoltage plus Network.res_touch_voltages(). Initial implementation uses a simple analytical surface-potential model in layered earth; higher-fidelity surface potentials come from groundfield via ImpedanceTable.

    Near term — external network import¶

    Building grounding networks by hand is the single most time-consuming step in any case study. Re-using existing distribution-network models from established power-system tools eliminates that work and makes groundinsight directly applicable to real network data. The two priority importers below cover the dominant tools in the German distribution-network space.

    • pandapower importer — new module src/groundinsight/io/pandapower_import.py exposing from_pandapower(net, *, defaults: ImportDefaults) -> Network. Maps pandapower bus, line, trafo (and optionally switch, ext_grid) tables to groundinsight Bus and Branch objects. Required user-supplied defaults: rho, frequencies, default BusType and BranchType (impedance formulas), plus a per-std_type override map for cable shields / overhead PEN conductors. Length is taken from line.length_km; transformer branches default to a configurable star-point impedance formula. Round-trip example notebook under notebooks/import_pandapower.ipynb. Shipped — gi.from_pandapower, gi.ImportDefaults, gi.preview_pandapower_import. The PowerFactory paths below are still open.
    • PowerFactory importer — new module src/groundinsight/io/powerfactory_import.py with two ingestion paths:
    • .dgs export (preferred, no PowerFactory installation needed) — from_powerfactory_dgs(path, *, defaults) parses the PowerFactory data-grid CSV/XML export and emits a Network.
    • Live PowerFactory Python API — from_powerfactory(app, *, defaults) for users running groundinsight next to a PowerFactory session (powerfactory.GetApplication()); kept behind a soft import so the dependency stays optional. Both paths share the same ImportDefaults schema as the pandapower importer.
    • ImportDefaults Pydantic model — common schema for all importers: rho, frequencies, default BusType / BranchType references, per-element-type overrides, and a hook for user-supplied resolver callbacks (resolve_bus_type(row) -> BusType). Lives in src/groundinsight/io/__init__.py so future importers (DIgSILENT NEPLAN, PSS®E raw files) reuse it.
    • CLI / notebook helper — groundinsight.io.preview_import(net, defaults) returns a Polars DataFrame summarising which buses and branches will be created and which elements were skipped (with reason), so users can validate the mapping before committing to a full network build. Shipped as gi.preview_pandapower_import.

    Near term — other¶

    • Codecov / Coveralls integration — upload coverage from CI and show a PR diff badge; currently the XML report is only uploaded as a workflow artifact.
    • CITATION.cff validation in CI — cff-validator step to catch broken metadata before a release is cut.
    • Release-notes template — the GitHub Release body is currently auto-generated from PR titles, which reads rough. Either a manual release_notes/vX.Y.Z.md workflow or a release-drafter config would give cleaner user-facing notes. (Partially addressed by the new CHANGELOG.md flow.)

    Medium term¶

    • MeasurementScenario abstraction — model the earthing measurement (auxiliary electrode at distance d, measurement-loop source) as a first-class object instead of an ad-hoc Fault. Lets the AP 1 reference-case studies (variation of auxiliary-electrode position) be expressed without notebook scaffolding. Add a measurement setup with current injection into the power system to the neighbour bus. Add a comparing function of real earthfault to, measurement with auxiliary electrode and current injection to the neighbour substation, to understand systematic errors.
    • Optional bus geometry (position_xy) — no hard dependency, but enables Carson distance calculations and map-style visualisations. Must stay optional so existing networks keep working.
    • Plot refactor: the matplotlib helpers are one-shot bar plots. Extract an optional Plotly backend so results can be explored interactively in notebooks and embedded in the docs site.
    • REST/HTTP API surface — the empty src/groundinsight/api/ package was reserved for this. Likely FastAPI-based, exposing run_fault and the res_* accessors. Decide scope (thin RPC vs. job-oriented) before writing code.
    • Performance: parallelise the per-frequency solve in ElectricalNetwork.solve_network with concurrent.futures (threads are enough — the work is in SciPy's native sparse LU, which releases the GIL). Roadmap item in the README.

    Long term¶

    • Kron reduction / multi-port model reduction — eliminate internal buses and emit a reduced-port Z (or Y) matrix. This is the groundinsight-side counterpart of the dissertation's AP 2: once a large reference network exists, reduce it to a transferable model class.
    • Time-domain extension — convert frequency-domain results into transient EPR / branch-current waveforms via inverse FFT, given a user-supplied fault-current time function. Needs design work on how to spec the input and what assumptions (linearity, bandwidth) to guard. Shipped — gi.TransientStudy with solver="fft" for exactly this, and solver="state_space" beyond it.
    • Typed impedance DSL — replace SymPy formula strings with a small typed expression tree so units and argument domains can be checked at construction time. Would also let the docs site render a formula catalogue automatically.
    • Grey-box measurement identification — given a measurement data set (e.g. from groundmeas), estimate bus grounding impedances and coupling parameters. Likely lives in a dedicated identification package or in groundmeas itself; the hook on the groundinsight side is the ImpedanceTable interface listed under the groundfield bridge.

    Safety assessment — the missing half of a grounding study. 0.5.0 added the equipment-integrity side (thermal limits for conductors and nodes); person safety is still unassessed.
