    Service layer and command line¶

    A notebook works with a Network directly. A front end — a GUI, a server, a batch tool — needs more: a project it can open and save, edits it can undo, long calculations off its event loop, and data it can send as JSON. The service layer groundinsight.api provides exactly that, without any physics of its own, and the command line groundinsight is built on it. This guide walks through a session, its commands and jobs, the JSON shapes and the command line. The script is service_layer.py; its output is at the end of the page. The design rules of the layer and its full API are on the service page.

    A session holds one project¶

    ProjectSession is one open project: ProjectSession.from_example(name) (the documented networks quickstart, minimal, mv_ring), ProjectSession.from_file(path) for a project file, or ProjectSession.from_store(store, key) for a server that keeps projects in a MemoryStore or a DatabaseStore. The constructor takes the resource limits a server sets per user — max_buses, max_branches (a larger file is refused on opening), max_job_runtime_s, max_undo and max_paths.

    A front end reads the project only through data-transfer objects (DTOs): summary() (NetworkSummaryDTO), tables() (the element tables of Network.to_tables), check() (the pre-flight check) and solve(fault) / result(fault) (FaultResultDTO: the key figures of Network.res_fault, the rows of res_buses and res_branches, the diagnostics as DiagnosticDTO, the revision it was computed from and whether it is stale).

    session = ProjectSession.from_example("quickstart")   # or ProjectSession.from_file("projekt.json")
summary = session.summary()                            # NetworkSummaryDTO
result = session.solve("fault_at_remote_bus")          # FaultResultDTO
rms = result.key_figures.rms()                         # the RMS row of Network.res_fault

    Every edit is a command¶

    A front end changes the project only through session.apply(command). The commands — AddBus, UpdateBus, RemoveBus and their counterparts for branches, sources, faults and the two type catalogues, plus SetFrequencies — call the library's editing API, so the library validates the input and derives the impedances. A command is atomic: a rejected one raises CommandError and changes nothing, not even the revision. session.undo() and session.redo() restore the network exactly; revision identifies an input state, and a result knows whether it is stale for the current one — the library's verdict (Network.is_result_stale), so undoing an edit makes the result current again. parse_command({"op": "update_bus", ...}) builds a command from JSON.

    report = session.apply(UpdateBus(name="bus_fault", fields={"specific_earth_resistance": 250.0}))
stale_after_edit = session.is_stale("fault_at_remote_bus")
session.undo()
stale_after_undo = session.is_stale("fault_at_remote_bus")

    Jobs¶

    Anything that can take longer than a moment runs as a job: session.submit_solve(fault) or session.submit(request) with a SolveRequestDTO, SolveAllRequestDTO, SweepRequestDTO, OutageStudyRequestDTO or MaxRhoRequestDTO returns a handle at once. The job runs on a snapshot of the network taken at submission, so editing can go on. handle.status() reports state and progress, handle.cancel() stops the job at the next unit of work, and handle.result(timeout=...) returns the DTO or raises JobCancelled, JobTimeout or JobFailed. The JobRunner of a session runs jobs in a thread by default; JobRunner(backend="process") runs them in a separate process, which costs the interpreter start but can stop a job hard and runs truly in parallel.

    handle = session.submit_solve("fault_at_remote_bus")  # returns at once
job_result = handle.result(timeout=60)                # FaultResultDTO, or raises
job_state = handle.status().state

    JSON in, JSON out¶

    Every DTO is a pydantic model with dto_schema_version; model_dump_json() is its wire format and never contains NaN or Infinity (a non-finite number is null). json_schemas() returns the JSON schema of every DTO, of all commands and of all job requests — the request and response schemas of a REST API. session.save(path) writes the library's project file (UTF-8, atomic, with schema_version) without stored results, so a file saved by a front end opens in a notebook and the other way round.

    wire = result.model_dump_json()                       # never NaN or Infinity
schemas = json_schemas()                              # JSON schema of every DTO
session.save("projekt.json")                          # library project file, without results
session.close()

    The command line¶

    Installing groundinsight installs the console script groundinsight (python -m groundinsight is the same):

    groundinsight run projekt.json                           # the only fault of the project
groundinsight run projekt.json --fault F1 --format json  # the FaultResultDTO
groundinsight run projekt.json --format csv              # the rows of res_fault
groundinsight check projekt.json                         # the pre-flight check

    groundinsight run opens the file in a session, runs the pre-flight check for the fault, solves it and prints the key figures per frequency and as RMS with the diagnostics (--format table, the default), the FaultResultDTO (json) or the key-figure rows with the columns of RES_FAULT_SCHEMA (csv). --phase-current-mode paths selects the legacy phase-current mode. groundinsight check prints every finding of check_network. The exit code is 0 on success, 1 when the check or the result reports an error, and 2 for a usage error (an unknown fault, a file that is not a project, run without --fault on a project with several faults).

    For the project saved by the script, groundinsight run projekt.json prints after a two-line header (version, network, fault and input digest):

    The GUI¶

    The separate distribution groundinsight-gui is a desktop and browser front end built with NiceGUI on this service layer; it is released together with the library and carries the same version. Its source is in the gui/ directory of the repository.

    pip install groundinsight-gui        # browser mode
python -m groundinsight_gui          # opens http://127.0.0.1:8080
